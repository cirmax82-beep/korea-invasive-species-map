# 교란생물 종합관리 · 시민 분포지도

환경부 지정 **생태계교란 생물**이 어디에 나타나는지, 시민 관찰(집단지성)과 기관 기록을 합쳐 보여 주는 공개 지도입니다.

- **참여(제보)**: 시민은 [iNaturalist](https://www.inaturalist.org) 앱으로 사진을 찍어 올립니다. 다른 참여자와 전문가가 사진을 보고 종을 확인하고, 의견의 3분의 2 이상이 일치하면 ‘검증됨’(연구 등급)이 됩니다.
- **지도(결과)**: 이 앱이 iNaturalist 관찰을 10분마다 실시간으로 받아 지도에 표시하고, GBIF에 공개된 기관·타 플랫폼 기록(국립생태원, 네이처링, 국립중앙과학관, 국립수목원 등)을 함께 보여 줍니다.

서버나 회원 관리가 필요 없는 정적 웹사이트라서, 파일을 웹 호스팅에 올리기만 하면 누구나 볼 수 있습니다.

- **공개 지도**: https://invasive.biogrideia.com/
- **참여 안내 바로가기**(홍보용): https://invasive.biogrideia.com/#join
- 예전 주소(`cirmax82-beep.github.io/korea-invasive-species-map/`)로 들어와도 새 주소로 자동으로 넘어갑니다.
- 새 주소는 호스팅케이알 DNS의 CNAME 레코드(`invasive` → `cirmax82-beep.github.io`)로 연결되어 있습니다. 이 레코드를 지우면 사이트가 열리지 않습니다.

## 연구용 자료 내려받기

| 형식 | 내용 |
|---|---|
| **엑셀(.xlsx)** | ‘안내’(만든 시각·범위·인용 방법·유의점) + 원하는 시트: 원자료, 종별 요약, 시도별 요약, 시도×종 기록 수, 시도×종 출현 여부(0/1), 연도×종, 시도×연도, 연월별 추이, 분류군별 요약, 자료 출처(기관·라이선스별), 0.1° 격자×종(긴 형식), 열 설명 |
| **CSV** | 원자료 한 표(UTF-8, 엑셀에서 한글 깨짐 없음). R·Python에 바로 읽기 좋음 |
| **GeoJSON** | 지점 자료(QGIS 등 GIS 프로그램용, WGS84) |

- **원자료 열(24개)**: 종 ID, 국명, 학명, 분류군, 지정 연도, 자료 종류, 플랫폼, 자료 기관, 자료 묶음, 관찰일, 연도, 월, 위도, 경도, 위치 오차(m), 위치 흐림, 시도 코드, 시도, 장소 설명, 관찰자, 기록 유형, 라이선스, 원본 ID, 원본 주소.
- **열 이름**: 한글 또는 영문(Darwin Core 용어: `scientificName`, `eventDate`, `decimalLatitude` 등) 중에서 고릅니다.
- **범위**: ‘모든 자료’ 또는 ‘지금 지도에 걸어 둔 조건 그대로’(분류군·종·연도·기록 종류).
- 기록마다 라이선스가 다릅니다(CC0, CC BY, CC BY-NC 등). 논문에 쓸 때는 ‘안내’ 시트의 인용 방법을 따르고, GBIF 자료는 GBIF.org에서 같은 조건으로 직접 내려받아 DOI를 인용하는 것을 권합니다.
- 전체 자료를 원자료까지 넣으면 약 12 MB입니다. 집계표만 필요하면 원자료 시트를 빼면 1~2 MB입니다.

## 내 컴퓨터에서 실행

폴더 안의 **`실행.bat`**을 더블클릭하면 `http://localhost:5173`에 열립니다(Python 필요). 직접 실행하려면:

```bash
python -m http.server 5173
```

## 자료가 들어오는 방식

1. **기본 자료(스냅샷)**: `data/inat-snapshot.json`(시민 관찰)과 `data/gbif-snapshot.json`(기관·타 플랫폼 기록). 방문자마다 수천 건을 새로 받지 않도록 미리 받아 둔 파일입니다.
2. **실시간 반영**: 앱이 열리면 기본 자료 이후 새로 올라오거나 상태가 바뀐(확인 중 → 검증됨 등) iNaturalist 관찰만 받아 합치고, 10분마다 다시 확인합니다. 상단 ‘실시간’ 표시를 누르면 바로 확인합니다.
3. GBIF에는 iNaturalist의 검증 기록도 들어 있으므로, GBIF 스냅샷에서는 iNaturalist 자료를 빼서 중복을 막습니다.

## 자동 갱신과 배포 (GitHub Actions)

`.github/workflows/pages.yml`이 기본 자료를 자동으로 새로 받고 사이트를 다시 배포합니다.

| 언제 | 하는 일 |
|---|---|
| 매일 03:00 (한국 시간) | iNaturalist 시민 관찰을 새로 받아, 바뀌었으면 커밋하고 배포 |
| 매주 월요일 03:30 | 위에 더해 GBIF 기관·타 플랫폼 기록도 새로 받음 |
| `main`에 직접 올릴 때 | 자료 갱신 없이 바로 배포 |
| 저장소 Actions 탭 → ‘자료 갱신과 배포’ → Run workflow | 둘 다 지금 바로 갱신 후 배포 |

외부 API가 잠시 실패하면 그날은 기존 자료로 배포됩니다. 진행 상황과 실패 알림은 저장소의 Actions 탭에서 볼 수 있습니다.

> GitHub는 저장소에 60일 동안 활동이 없으면 예약 실행(schedule)을 멈춥니다. 자동 갱신 커밋이 계속 생기면 보통 유지되지만, 멈췄다는 메일을 받으면 Actions 탭에서 다시 켜 주세요.

내 컴퓨터에서 직접 새로 받으려면:

```bash
python tools/inat_snapshot.py
```

```bash
python tools/gbif_snapshot.py
```

## iNaturalist 프로젝트(선택)

참여자를 모으고 싶다면 iNaturalist 계정으로 ‘한국 생태계교란 생물’ 같은 **컬렉션 프로젝트**를 만들 수 있습니다. 장소를 South Korea로, 분류군을 지정 종으로 정하면 조건에 맞는 관찰이 자동으로 모입니다. 프로젝트 페이지 주소를 참여하기 화면에 함께 걸어 두면 좋습니다. 프로젝트를 만들려면 계정 조건이 있을 수 있습니다.

## 유의할 점

- 기록은 사람이 많이 다니는 도시·관광지에 몰리는 경향이 있습니다. 기록이 없다고 그 지역에 없다는 뜻은 아닙니다.
- ‘확인 중’ 기록은 종이 틀렸을 수 있습니다. 정확한 분포가 필요하면 ‘검증된 것만’을 쓰세요.
- 지정 목록은 위키백과·언론 보도를 종합한 것입니다. 법적 기준은 국가법령정보센터의 「생태계교란 생물 지정 고시」이니 확인 후 `js/data-species.js`를 고치세요.
- 사진은 관찰자가 CC 라이선스로 공개한 것만 출처와 함께 보여 주고, ‘모든 권리 보유’ 사진은 링크로만 연결합니다.
